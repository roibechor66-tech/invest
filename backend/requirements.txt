# Pinned explicitly. passlib 1.7.4 is incompatible with modern bcrypt in
# two separate ways, both hit while getting this project running locally
# for the first time (Windows, fresh pip install with no pin at all pulled
# bcrypt 5.0.0):
#   1. bcrypt>=4.1 removed bcrypt.__about__, which passlib's backend-
#      version probe reads → AttributeError on every hash/verify call
#      (register/login both 500/401).
#   2. Even bcrypt==4.0.1 (which still has __about__) raises
#      "ValueError: password cannot be longer than 72 bytes" during
#      passlib's own startup self-test (detect_wrap_bug), because
#      bcrypt>=4.0 raises on >72-byte input instead of silently
#      truncating it the way older bcrypt did.
# bcrypt==3.2.2 predates both changes and is the version most commonly
# recommended alongside passlib 1.7.4 for exactly this reason.

# Replaces Financial Modeling Prep (FMP) for financials/multiples/
# historical prices (app/services/fundamentals.py, portfolio_performance.py)
# — free, no API key needed, pulls from Yahoo Finance. Pulls in pandas as
# a dependency automatically.
#
# Un-pinned from the original ==0.2.44 after discovering (in production, on
# Render) that EVERY ticker failed identically with "Failed to get ticker
# '<X>' reason: 'str' object has no attribute 'name'" (logged as "possibly
# delisted; no timezone found") — this happened even for well-covered,
# definitely-not-delisted tickers, and even after removing the curl_cffi
# session that was first suspected (see app/services/yfinance_session.py).
# A failure that uniform, on the very first internal call yfinance makes
# per ticker (fetching exchange/timezone metadata), is the signature of
# Yahoo's endpoint returning something yfinance 0.2.44 doesn't know how to
# parse any more (an HTML/error page instead of JSON, or a stricter
# crumb+cookie handshake Yahoo added after this yfinance version was
# released) — not a per-ticker or rate-limit issue. yfinance ships frequent
# hotfixes for exactly this kind of Yahoo-side API change, so this is
# loosened to a minimum version instead of an exact pin, letting `pip
# install` on each deploy pick up whatever the latest compatible release
# is. **Not yet verified against a live deploy** (this environment has no
# outbound network to PyPI to confirm an exact newer version number) — if
# the same error persists even after this, the real fix is switching this
# data source to Finnhub (already used for live quotes, see
# app/services/market_data.py) instead of continuing to patch yfinance.
yfinance>=0.2.50
